## 核心业务闭环验证

```
提交报修 → 自动派单(AUTO, 处理中) → 接单 → 完成 → 验收不通过(退回重修)
        → 二次完成 → 验收通过(5星) → 已完成；流转日志完整记录每一步
```

## 验证过的防护逻辑（均正确拒绝）

- 状态机非法流转：处理中验收、重复完成、已派单撤销、已完成/关闭后关闭与催办
- 角色越权：住户/维修工访问管理员接口、住户派单/统计/候选
- 数据越权：非报修人查看他人工单详情、非报修人催办
- 参数校验：登录失败、注册重名、建单缺参、派单缺维修工/派给住户、验收通过不打分

## 过程说明

第一轮 89 例中 4 例"失败"，经排查为测试脚本沿用 V1.0 假设所致，并非产品缺陷：
提交工单后 `OrderService.create()` 会立即触发智能派单（V2.0 特性），工单直接进入"处理中"；
"已派单工单不可撤销、提示联系管理员关闭"亦为正确业务保护。脚本已按 V2.0 行为修正，
并通过临时关闭 `autoDispatchEnabled` 开关补测了待派单分支。

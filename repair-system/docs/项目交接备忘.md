### 4.3 工单状态模型（现状，勿擅改编码）

```java
STATUS_PENDING_DISPATCH   = 0  // 待派单
STATUS_PROCESSING         = 1  // 处理中（已派单未接单 与 维修中 混用，是当前主要痛点）
STATUS_PENDING_ACCEPTANCE = 2  // 待验收
STATUS_COMPLETED          = 3  // 已完成
STATUS_CLOSED             = 4  // 已关闭
```

流转日志动作：`SUBMIT / ASSIGN / AUTO_ASSIGN / REASSIGN / ACCEPT / REFUSE / FINISH / PASS / REJECT / CANCEL / CLOSE / URGE`

> `REJECT` 专指住户验收不通过；维修工拒单是 `REFUSE`，两者不要混用。
> 状态 1 的用户感知已拆为「待接单（`workerAcceptTime` 为空）/ 维修中（非空）」，但**编码未变**，统计口径仍按 5 态计数。

| **A5** | 管理员待办提示条 | ⬜ 未开工 | 纯前端，用已加载列表在前端聚合：待派单 N（>24h N）、待接单超 12h N、待验收超 72h N，点数字即筛选 |

**剩余工作顺序建议**：A4 → A5 → A3（三项全部纯前端，零风险；A3 只剩一处耗时展示）。

> 另：**派单规则专项**已于 2026-10-25 定稿落地，见 6.1 节，不属于 A1~A5 编号范围。

**A2 实测动线**（用户启动后可走一遍）：
管理员在工单管理对一笔「处理中」工单点「改派」→ 选另一位师傅 → 原师傅收到"已被改派"消息、新师傅收到新任务 → 新师傅在任务台看到「待接单」，此时点「拒单」填原因 → 工单退回待派单、管理员收到通知 → 管理员再派给第三人 → 该师傅点「接单」→ 状态变「维修中」→ 点「完成维修」→ 住户验收。

> 注意：A2 之后**未接单不能直接报完工**（会提示"请先接单再报完工"），这是刻意加的门禁。

**验收动线**（可直接当答辩演示脚本）：
住户提交 → 自动派单，住户侧显示"已派单（待接单）" → 李师傅拒单并填原因，工单回待派单、管理员收通知 → 管理员顶部提示条数字 +1，改派给王师傅，双方收通知 → 王师傅接单变"维修中" → 报完工附照片与耗时 → 住户看到五节点时间轴 → 验收评价完成，提示条归零。

## 6.1 派单规则定稿（2026-10-25，已落地）

### A. 自动派单：5 个条件**全部满足**才触发

| # | 条件 | 数据来源 | 不满足时 |
|---|---|---|---|
| 1 | 自动派单总开关 = 开 | `dispatch_rule.auto_dispatch_enabled` | 转人工 |
| 2 | 该报修类型允许自动派单 | `repair_type.auto_dispatch`（本次新增列） | 转人工 |
| 3 | 存在技能匹配且在岗的维修工 | `worker_skill` + `user.status` | 转人工 |
| 4 | 至少一人未满负荷（未完成单数 < `max_load`） | 实时统计（处理中+待验收） | 转人工 |
| 5 | 可派候选人数 ≥ `min_candidates`（本次新增列，默认 1） | 实时统计 | 转人工 |

满足后按既有公式打分取 Top1：`负荷×w_load`（紧急单 `× (1+urgency_boost)`）+ `历史评分×w_rating` + `楼栋熟悉度×w_familiarity`。

### B. 转人工时系统做什么（不再静默）

1. 工单时间轴写入 `HOLD` 节点：「转人工派单：<原因>」（详情弹窗中为灰色节点）；
2. 给全部在岗管理员发站内消息：「工单【单号】未自动派单(<原因>)，请人工派单」；
3. 提交报修接口把原因返回前端，住户侧 toast 显示「本次转人工派单：<原因>」。

### C. 需要管理员手动派单的场景

- 总开关关闭（全部工单人工派）；
- 该报修类型设为人工（默认：电梯故障，需联系维保单位）；
- 无技能匹配的师傅 / 技能师傅全部被禁用；
- 师傅全部满负荷，或可派候选少于下限；
- 维修工拒单后工单退回待派单——**不自动重派**，由管理员决定派给谁。

### D. 类型 × 技能现状（`upgrade_v31_dispatch.sql` 已应用）

| 报修类型 | 派单方式 | 可接单师傅 |
|---|---|---|
| 水电维修 | 自动 | 李师傅 |
| 门窗维修 | 自动 | 王师傅 |
| 电梯故障 | **人工** | 王师傅 |
| 门禁系统 | 自动 | 李师傅 |
| 公共照明 | 自动 | 李师傅 |
| 其他 | 自动 | 王师傅 |
| **网络故障（新增）** | 自动 | **周师傅（仅此一项技能）** |

> 网络故障演示点：住户提交「网络故障」→ 唯一候选是周师傅 → 自动派给他；把周师傅禁用（或让他堆满 5 单未完成）→ 该类型工单转为人工并写明原因。这就是"技能专精 + 规则兜底"的完整演示。

### E. 超时自动改派

- 处理中超过 `reassign_hours`（48h）→ 排除"已试过的人"和"满负荷的人"后改派次优，最多 `reassign_limit`（2）次，超限通知管理员；
- 类型为人工派单的（电梯故障）**不自动改派**，直接通知管理员介入。

### F. 配置入口（全部在管理端，改完即时生效）

| 入口 | 路径 | 可改内容 |
|---|---|---|
| 派单规则（菜单） | `/dispatch-rule` | 总开关、负荷上限、候选下限、三项权重、紧急放大、改派阈值/上限、存档条数 |
| 字典管理 → 报修类型 | `/dict-manage` | 每个类型的「自动 / 人工」开关（表格内直接切换） |
| 用户管理 → 维修工「技能」 | `/user-manage` | 勾选该师傅能接的报修类型；不勾则永远收不到自动派单 |
| 接口 | `GET/PUT /api/dispatch/rule`、`GET/PUT /api/users/{id}/skills` | 供二次开发 |
